# Flight Booking

Реализация всех пунктов `task.html` (1–10).

## Решения

Python 3.12, синхронные FastAPI/grpcio, psycopg 3 и PostgreSQL 17.
Альтернативы: Go компактнее при развёртывании, Java/Spring предлагает готовую
инфраструктуру, но для этого самостоятельного проекта Python позволяет явно
показать транзакции, gRPC interceptors и алгоритмы отказоустойчивости.
Выбор стека сделан исполнителем; условие разрешает любой язык.

Booking предоставляет REST, Flight — только gRPC. Собственные PostgreSQL и
версионированные SQL-миграции при старте каждого сервиса. Денежные суммы —
Decimal/NUMERIC, в protobuf и JSON — десятичные строки, валюта RUB.
Дата поиска — календарная дата UTC. В proto даты — Timestamp, статусы — enum.

Резервирование сериализуется по booking_id advisory lock и блокирует рейс
SELECT FOR UPDATE. Уникальный booking_id обеспечивает идемпотентность;
повтор с иными параметрами запрещён. Release идемпотентен и записывает
отмену даже для отсутствующего резерва, чтобы запоздавший Reserve не отнял места.

Распределённой транзакции между PostgreSQL нет. Перед резервированием Booking
сохраняет durable intent. Запись booking и завершение intent атомарны локально.
После ошибки/падения незавершённые intents компенсируются повторяемым Release.
Синхронная компенсация выполняется сразу, фоновая — после перезапуска и сбоев.
Отмена booking сохраняется как durable задача и повторяется фоновым обработчиком.
API возвращает CONFIRMED только после успешного резерва и локального commit.

API key через metadata проверяется interceptor-ом для всех gRPC методов.
Клиентский interceptor делает максимум 3 попытки только при UNAVAILABLE и
DEADLINE_EXCEEDED; backoff 100/200 ms. Circuit breaker охватывает логический
вызов целиком, имеет окно ошибок, один HALF_OPEN probe и настройки из env.

Redis Sentinel: master, replica, 3 sentinel, quorum 2. Cache-aside с TTL 300 s.
Для устранения гонки «старое чтение после invalidation» ключи версионируются
монотонной ревизией PostgreSQL, читаемой в той же транзакции, что и данные.
Мутация увеличивает ревизию атомарно; прежняя версия становится недоступной.
Инвалидация не зависит от доступности Redis. Redis outage приводит к чтению БД.

## Проверка

Unit tests: retry, circuit breaker и валидация. Интеграционные тесты с реальными
PostgreSQL, Redis и gRPC: REST flow, атомарность, гонки, идемпотентность,
аутентификация, компенсация и кеширование. Docker Compose поднимает всё одной
командой, содержит тестовый profile. ER-диаграмма и примеры запросов в README/docs.
